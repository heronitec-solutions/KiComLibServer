Component libraries for KiCad.

KiComLib keeps symbols, footprints, 3D models, datasheets, and ordering data in one place. KiCad reads them as an HTTP library, the plugin keeps the files in sync, and Git projects are checked against that exact revision.

01 — Features

From the component to manufacturing output.

A catalog for the library, a warehouse for stock, a comparison for projects, and a history that makes overwrites visible.

Directly in KiCad

The plugin lives in the PCB editor and syncs symbols, footprints, multiple 3D models per footprint, datasheets, and templates with the server. A KiCad HTTP library brings the component fields into the schematic. The plugin creates every path automatically.

Catalog with lifecycle

In the catalog, symbols and footprints are linked to manufacturers, part numbers, distributors, order numbers, and datasheets. Alternatives and replacements can be managed as well.

Distributors connected

Look up parts through TrustedParts and import component data through the DigiKey, Mouser, Farnell, Arrow, and TME APIs.

Versioned commits

Every change is stored in the history and can be reverted at any time.

Projects from Git

KiCad projects from GitLab, GitHub, and other Git servers are mirrored read-only. The BOM is checked against the catalog, and differences in the schematic or board can be highlighted visually.

Warehouse

Stock, storage location, and batches. An entry is tied to a catalog part, and it can also be created manually. Individual batches such as “ordered” or “in stock” can be managed.

03 — Workflow

From the catalog into manufacturing.

  1. Maintain the catalog

    Create parts, symbols, and footprints in the web UI or through the plugin. Manufacturers, order numbers, and lifecycle are part of that.

  2. Track stock

    Storage location and batch for a catalog part or a manual entry. Ordered, Received, In Stock, Reserved, and Empty stay visible in the list.

  3. Sync into KiCad

    Check shows the difference. Sync applies it with a commit message and writes the files locally.

  4. Mirror a project

    Enter host, credentials, and repository. KiComLib follows the commits and renders the schematic and board.

04 — Deployment

Start with Docker Compose.

PostgreSQL, the web API, the KiCad runner, and optionally an NGINX reverse proxy as a Docker Compose file. The files are in deployment.

The default login for a fresh install is admin / kicomlib. You have to change it after the first login.

HTTP

Copy .env.example to .env and set KICOMLIB_DB_PASSWORD and KICAD_RUNNER_TOKEN. In compose.yml, set PUBLIC_BASE_URL to your own address. The server listens on port 80.

cd deployment
cp .env.example .env
docker compose up -d

HTTPS

Same as HTTP, and also place the certificate and key at certs/fullchain.pem and certs/privkey.pem. Then start compose_ssl.yml. The server listens on ports 80 and 443.

cd deployment
cp .env.example .env
docker compose -f compose_ssl.yml up -d

Plugin

Search for KiComLib in the KiCad Plugin and Content Manager. For the current revision, clone the repository into the plugin directory and restart KiCad.

git clone --depth 1 https://github.com/heronitec-solutions/kicomlib
